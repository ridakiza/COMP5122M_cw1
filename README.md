## How we use GitHub

1. **Work on your own branch**, never directly on `main`:
   ```bash
   git checkout -b p3-awareness        # use your role + topic
   git add <files>
   git commit -m "Add Q30 gap calculation"
   git push -u origin p3-awareness
   ```
2. **Open a pull request** when something is ready, and ask one other person to review it.
3. **Merge early only when others need it:**
   - P1's cleaning script and cleaned data go into `main` as soon as they work, because everyone uses them.
   - P3's gap code goes into `main` once it works, so P4 can copy it for Q31.
   - Everything else stays on its branch and is merged at the end for the final submission.
4. **Pull from `main` before you start each day** so you're working on the latest data:
   ```bash
   git checkout main && git pull
   git checkout <your-branch> && git merge main
   ```

## Data notes

- Recode 8/9/98/99 ("don't know" / "refused") as missing, but **keep 8 = "not sure" on Q32** (`aireg_*`).
- Real answers that look like codes, so **don't** blank them: age `97` = "97 or older"; `internetfreq` `6` = "does not use the internet".
- Australia stores age and gender in `age_australia` / `gender_australia` (age in bands only) and has no internet-use question.
- Refused ages (98/99) are partly recovered from the `d_age_*` follow-up, using **each country's own bands** (they differ by country).
- Always use `weight`. Pew says it must be used for population estimates, and with it our numbers match Pew's published topline exactly.
- Some 18–29 groups are small (80 people in Hungary and South Korea), so report gaps with 95% intervals.
